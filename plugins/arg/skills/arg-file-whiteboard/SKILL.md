# Whiteboard files (`.whiteboard`)

A freeform 2D canvas of nodes (shapes, sticky notes, text, tables, sections, images, generators) and edges (connectors), stored as React Flow JSON.

## CRUD

Use your active Arg access method (`arg-mcp` / `arg-cli` — see `arg-files`) and the shared rules in `arg-files`. Whiteboard-specific: read the board first to learn existing nodes and their coordinates; to remove a node, edit the JSON and drop it plus any edges that reference it.

## Schema essentials

Top-level: `version` (use `1`), `nodes`, `edges`. Every node and edge needs a **unique `id`** (e.g. `n1`, `edge-1`). Pan/zoom is stored client-side per viewer, not in the file, so `viewport` is optional - include `viewport` (`{ x, y, zoom }`) only to hint the initial view; it's honored on first open, then superseded by the viewer's own pan/zoom.

**Node** — `id`, `type`, `position` (`{x,y}` canvas px), `width`, `height`, `data` (whose `kind` matches the type).

- `type: "shape"` — `data.shape`: common variants `rectangle` / `rounded-rectangle` / `diamond` / `circle` / `ellipse`, plus diagram variants `triangle` / `parallelogram` / `pentagon` / `hexagon` / `octagon` / `trapezoid` / `star` / `arrow-right` / `arrow-left` / `arrow-left-right` / `bubble` / `cloud` / `cross` / `barrel` / `brace-left` / `brace-right` / `chevron` / `notched-chevron` / `predefined-process` / `terminator` / `document` / `multiple-documents` / `manual-input` / `preparation` / `direct-access-storage` / `internal-storage` / `manual-operation` / `delay` / `stored-data` / `merge` / `or` / `summing-junction` / `display` / `off-page-connector` / `note` / `magnetic-tape` / `multi-process` / `lined-shaded` / `lined-document` / `divided`; `label`, `fill`, `textColor`.
- `type: "sticky"` — `label`, `fill`, `textColor`.
- `type: "text"` — `label`, `fill` (often `transparent`), `textColor`, `fontSize`; optional `fontFamily` is a single Google or system font family name such as `Instrument Serif` or `Arial`.
- `type: "path"` — freehand or imported line art: `d` (SVG path), `viewBoxW`, `viewBoxH`, `strokeColor`, `strokeWidth`; optional `strokeOpacity`, `strokeDasharray`, `arrowStart`, `arrowEnd`.
- `type: "generator"` — action-registry generation node. `label` is the editable node name and the filename stem for generated image/video/3D/PDF files; `data.actionKind`: `text-to-text` / `image` / `video` / `3d` / `pdf`; `prompt`; `model`; `outputKind`: `text` / `image` / `video` / `pdf` / `3d`; optional `aspectRatio` for image generators running without image inputs (`1:1`, `4:3`, `3:4`, `16:9`, `9:16`, `3:2`, `2:3`); optional `quality` (`low`, `medium`, `high`) for image generators on models that expose one - omit it to take the model default, and note higher settings cost more per image; optional `outputFolder`, an absolute workspace folder (`/renders`, `/` for the root) that generated image/video/3D/PDF files are written to - absent means the per-type default destination; optional `model3d` camera pose for generated 3D outputs; optional `pdfInputOrder` source-node id array for PDF concat order; optional `autoRunDownstream: true` to trigger directly connected downstream generators after a successful run; optional `runHistory` array of successful generated outputs and `selectedRunHistoryId` for the displayed entry; optional `generatedText` for text output, optional `generatedFileId` durable workspace file id plus `generatedSrc` readable path snapshot for image/video/pdf/3D output, `lastRunId`, `lastError`.
- `type: "table"` — `rows`, `cols`, `cells` (row-major, length = `rows*cols`), `headerRow` (bolds the first row), `fontSize`.
- `type: "section"` — a labelled frame grouping nodes on top of it; set `zIndex: -1` and size it to enclose its contents.
- `type: "image"` — a picture. `src` is a workspace path (e.g. `/diagrams/architecture.png`) or an external image URL; optional `sourceUrl`, `altText`. Use real files/URLs — don't invent paths.
- `type: "icon"` — a Lucide icon; `iconName` is the kebab-case Lucide name (e.g. `database`, `cloud`, `git-branch`). Use to label or decorate diagram nodes.
- `type: "emoji"` — a single emoji stamp; put the character in `emoji`.
- `type: "object3d"` — a live 3D model. `src` is a workspace model path (`.glb` preferred; `.gltf/.obj/.stl/.ply/.fbx/.3mf/.usd/.usda/.usdc/.usdz`, STEP solids `.step/.stp`, and Gaussian splats `.splat/.ksplat/.spz` accepted) — reference a real uploaded model, don't invent paths (binary models can't be created with a write). Optional `fileId` (`argfile_<uuid>`) is the durable file-registry handle the board mints automatically on first open so the reference self-heals across renames/moves — omit it when authoring. Optional `model3d` sets the camera pose: `yaw` (deg), `pitch` (-89..89), `distance` (0.2..50), `fov` (10..90), `panX`/`panY` (-5..5), `environment` (`studio`/`sunset`/`dawn`/`night`/`neutral`), `exposure` (0.2..3), `background` (hex or null). Omit `model3d` for a studio-lit default.
- `type: "embed"` — a live iframe for an embeddable URL. Put the page URL in `url` — it's resolved to the provider's embed at render time, so use the normal share/watch link (never hardcode an `/embed` src). Recognised providers include YouTube, Vimeo, Loom, Spotify, SoundCloud, Figma, Miro, Canva, Framer, CodePen, CodeSandbox, Replit, Excalidraw, Tableau, Streamlit, Typeform, Tally, TikTok, Twitter/X, Instagram, LinkedIn, Reddit, Pinterest, GitHub Gist, and Giphy.
- `type: "bookmark"` — a rich link-preview card for a non-embeddable URL. Set `url`; the title/description/image/favicon are unfurled at render time (don't fabricate them). Prefer `embed` for the providers above and `bookmark` for ordinary web links.
- `type: "stock"` — a live price card (quote + sparkline) for a ticker. `symbol` is the ticker (e.g. `AAPL`, `BTC/USD`); `range` is one of `1D`/`1W`/`1M`/`3M`/`6M`/`1Y`/`5Y`. Prices are fetched at render time — never hardcode them.
- `type: "weather"` — a live weather card (current conditions + forecast sparkline) for a location. `location` is a place name; when exact coordinates are known, also set `latitude`, `longitude`, `timezone`. `days` is one of `1`/`3`/`7`/`10`/`16` (1 is today only); `unit` is `celsius` or `fahrenheit`; `chart` is `temperature`/`precipitation`/`wind`/`none` (default `temperature`). Fetched at render time — never hardcode it.
- `type: "fileEmbed"` — embeds a live preview of any workspace file (PDF, video, CSV, design, another whiteboard, etc.) on the canvas. `fileId` is the file-registry UUID or workspace path (e.g. `/reports/q1.pdf`) — the renderer resolves either form and survives renames. A `.design` embed also accepts `embedPage`, the 0-based artboard index shown as a flat preview and sent to generators. Display-only on the board.
- `type: "meetingRecorder"` — a native meeting-recorder card: the user records mic (+ optional system) audio, it's transcribed, and an AI summary with citations is streamed. It shares the same capture/transcribe/summarize engine as the MDX `<Recording />` block. Author it empty (`{ "kind": "meetingRecorder" }`) so the user can hit Record — the capture is a live user action, never something to pre-fill. Finalized content round-trips as optional data: `title`, `notes`, `transcript`, `summary`, `citations` (JSON string), `audioPath`, `audioMime`, `durationMs`, `phase` (`new`/`recorded`), plus config `instructions` (summary template id, default `auto`), `transcriptionProvider` (`deepgram`/`elevenlabs`/`native`), `keepAudio`, `timestamps`. Never fabricate a transcript or summary.

Standalone text nodes accept an optional single-family `fontFamily`. `data` also accepts optional text styling on any node: `fontSize`, `bold`, `italic`, `strikethrough`. Default sizes: shape `220×132`, circle `156×156`, sticky `220×180`, text `240×96`, emoji `100×100`, icon `100×100`, image `1024×768`, path `120×80`, object3d `360×360`, embed `640×360`, bookmark `320×300`, table `440×200`, section `520×360`, stock `300×180`, weather `300×190`, fileEmbed `460×360`, meetingRecorder `400×320`. Set explicit `width`/`height` for non-rectangular diagram shapes when the symbol has a natural aspect ratio.

**Edge** — `id`, `source`, `target`, `sourceHandle`/`targetHandle` (`top`/`right`/`bottom`/`left`), `type` (e.g. `smoothstep`), `markerEnd` (`{ type: "arrowclosed", width, height, color }`), optional `data.label`. Edge `data` may also carry `strokeColor`, `strokeWidth`, `strokeOpacity`, `strokeDasharray`, `arrowStart`, and `arrowEnd`.

Generator data flow uses arrow direction. Incoming sticky/text/shape/table text, upstream text-generator output (`generatedText`), and connected file embeds that resolve to Markdown/MDX/text files are appended to the generator prompt; an edge `data.label` prefixes that source as `label: text`. Incoming image nodes, upstream generator image outputs, and connected file embeds that resolve to image files provide source images for image, video, 3D, and text-to-text vision prompts; an image node contributes its alt text (not raw node JSON) as prompt context, and an edge `data.label` on an image-consumed connection is appended to image, video, and text-to-text prompts as an intent line (`Input image: label`, or `Input image N: label` numbered by send order when the model consumes multiple images) so labels like "style reference" or "background" convey each image's role. Google Maps iframe/embed URLs, KML/KMZ file embeds with point placemarks, and sticky/text nodes containing a recognizable address or latitude/longitude are converted through the server-side Google Street View Static proxy into image inputs; the editor keeps up to six random Street View captures per location in a local session cache and reuses them randomly after that. For image and video generators, connected `object3d` nodes, upstream 3D generator outputs, and 3D file embeds are rendered to a PNG screenshot of their current whiteboard orbit viewport and passed as image inputs. Connected `.design` file embeds with `embedPage` are rendered to one JPEG of that selected artboard and sent as one image input in every generator mode; the artboard's name qualifies that image's intent line (`Input image: label (Cover)`). Legacy design embeds without `embedPage` keep the historical behavior: artboards are sent in document order up to a request-size budget - at most the first 8, and fewer when they are large - until a user saves a selection. An empty or unparseable `.design` file is reported as unreadable rather than sent as a blank image. Connected `.psd` file embeds are flattened to a single PNG image and sent as one image input, in every generator mode; a PSD whose PNG is too large to inline is sent as a JPEG of the same flattened composite instead, and the run warns that transparent areas were flattened to white. An empty or unreadable `.psd` file is reported rather than sent as a blank image. 3D generator outputs can be double-clicked in the editor to orbit, pan, and zoom; the current pose is stored as `model3d` and is used by downstream screenshots. Image generators auto-detect connected image inputs: no image input runs text-to-image, while any connected image input runs image-to-image and filters available models to that registry. Video generators use the same detection: no image input runs text-to-video from connected text context, while any image input runs image-to-video and filters available models to that registry; video generators do not expose a local prompt field and use the first image when image input is present. 3D generators use the same detection: no image input runs text-to-3D, while any image input runs image-to-3D and filters available models to that registry. Image generators forward multiple connected images only when the selected image-to-image model supports plural image inputs (for example GPT Image or Nano Banana); otherwise they use the first image. 3D generators use the first image. PDF generators concatenate incoming HTML, Markdown/MDX, text, image nodes, image file embeds, `.design` file embeds, `.psd` file embeds, and upstream image/text generator outputs; Markdown/MDX is rendered to HTML, workspace images embedded in those files are inlined, a selected `.design` source contributes one figure (legacy design embeds contribute one figure per artboard), a `.psd` source contributes one figure, and `pdfInputOrder` controls concat order.

By default an image/video/3D generator saves next to its first source image in a `<source-base>-edits/` folder (or `/generated` when no source anchors the run), and a PDF generator saves beside the board. Setting `outputFolder` overrides those defaults and every generated file lands in that folder instead. The node's `label` supplies the filename stem and the generated file type supplies the extension, so a node named `Campaign hero` produces `Campaign hero.png`, `Campaign hero.mp4`, `Campaign hero.glb`, or `Campaign hero.pdf` according to its mode. A repeat run keeps the earlier file and increments the new name as `Campaign hero-1.ext`, `Campaign hero-2.ext`, and so on.

`autoRunDownstream` is stored per generator node and is off by default. When enabled on a completed generator, it triggers directly connected downstream generator nodes using arrow direction; each downstream node continues the chain only if its own `autoRunDownstream` is also true. `runHistory` stores successful generated outputs on the node; selecting a history entry sets `selectedRunHistoryId` and swaps the displayed `outputKind` plus `generatedFileId`/`generatedSrc` or `generatedText`.

In the editor, right-click a generator node and choose Add next generator to quickly place a downstream generator of another type, connected from the source's right handle to the new node's left handle.

## Tips

- Space nodes 200–350px apart; lay flows left→right or top→bottom.
- Use semantic colors — blue=info, green=success, red=urgent, yellow=warning, purple=feature.
- `\n` in a `label` is a line break.
